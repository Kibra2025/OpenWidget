DualSense HID protocol references
================================

OpenWidget implements the DualSense battery protocol independently using
the existing HidSharp dependency and Windows HID/SetupAPI interfaces. It does not
bundle or link the DualSenseClient application or its .NET 10 assemblies.

Protocol reference:
https://github.com/DualSenseClient/DualSenseClient

Additional protocol reference for Bluetooth input CRC32 (prefix 0xA1), calibration
GET_FEATURE report 0x05 (41 bytes), and USB/Bluetooth report lengths:
https://github.com/torvalds/linux/blob/master/drivers/hid/hid-playstation.c

USB uses input report 0x01, with the payload beginning at byte 1; Bluetooth uses
input report 0x31, with the payload beginning at byte 2. Battery and power flags
are at payload offsets 52 and 53. Simple Bluetooth report 0x01 carries no battery
data and is never decoded as a USB report, even if padded to 78 bytes by Windows.

Battery percentages follow the referenced DualSenseClient revision: discharging
levels 0..10 map to min(level*10+5,100); charging levels map to max((level-1)*10,0).
Completed charging is 100%. Invalid levels and unknown/error power states have
no percentage. The result is an indication in approximately ten-percent steps,
not a measurement accurate to one percent.

All communication is input or GET_FEATURE. No output/SET_FEATURE reports,
rumble, lights, trigger effects, profiles, pairing changes or drivers are used.
Reading calibration over Bluetooth requests full telemetry from the controller;
it does not write calibration values.
